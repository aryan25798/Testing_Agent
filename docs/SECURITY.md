# Security & DevSecOps Architecture

The Testing Agent Platform enforces strict security boundaries designed for enterprise QA environments.

---

## 1. Zero-Credential Exposure

- Actual credentials, API tokens, and secret keys reside exclusively in `.env` or an approved secret manager.
- `.env` and `.venv/` are strictly excluded from version control via `.gitignore`.
- API keys are never exposed in REST API responses, UI text, logs, or database records.

---

## 2. Safe Synthetic Test Data Generation

- **Agent 3 (Test Case Design Agent)** is hard-constrained never to use real customer personally identifiable information (PII).
- All generated datasets (emails, phone numbers, credit cards, addresses) use synthetic data formats (e.g., `@example.com` domains, test card numbers).

---

## 3. Subprocess & Sandbox Execution Isolation

- Automated test scripts generated by **Agent 4** are never executed directly inside the main application or web server process.
- **Agent 5 (Execution Agent)** executes test code inside isolated Python subprocesses with:
  - Per-test execution timeouts (30s maximum limit)
  - Isolated temporary workspaces wiped immediately after completion
  - Memory and process monitoring
  - Protection against malicious shell injection.

---

## 4. Human-in-the-Loop Approval Gates

The AI agents cannot perform high-impact operations autonomously:
- Cannot write to external client repositories without diff review and approval.
- Cannot push commits to Git without authorization.
- Cannot run destructive commands or test against production systems without explicit confirmation.
